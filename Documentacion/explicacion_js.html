Funcionamiento de los JavaScript del front CINE NOIR

TPI Programación II · Carpeta Front_Cine_API/js

El front no usa frameworks: es JavaScript del navegador dividido en 8 archivos, uno por responsabilidad. Primero va la idea general, después cada archivo y al final un ejemplo completo de una compra.

1. Idea general

Módulos

Cada archivo es un módulo de JavaScript. Comparte funciones con export y usa las de otros archivos con import:

// api.js
export async function api(endpoint, opciones) { ... }

// cliente.js
import { api } from "./api.js";

En index.html se carga un solo archivo:

<script type="module" src="js/main.js"></script>

El navegador lee los import de main.js y carga solo los demás archivos. Por eso no funciona con doble clic (file:///): el navegador bloquea los módulos que no vienen de un servidor. Hay que abrirlo con Live Server.

Quién usa a quién

                main.js  (arranque y navegación)
          ┌────────┼────────┬───────────┐
       auth.js  cliente.js  admin.js  dashboard.js
          │        │          │           │
          └────────┴────┬─────┴───────────┘
                 api.js   ui.js   config.js   (archivos base)
  • Los archivos de arriba manejan pantallas.
  • Los de abajo son herramientas que usan todos.
  • Solo api.js habla con la API. Si mañana cambia la forma de llamar a la API, se toca un solo archivo.

Es una página única (SPA)

Todas las pantallas están en index.html desde el principio, pero ocultas. JavaScript muestra u oculta secciones con la clase d-none de Bootstrap. No se recarga la página al navegar.

2. config.js — configuración

Dirección de la API:

  • getApiUrl() devuelve la dirección guardada en localStorage o, si no hay ninguna, https://localhost:7032.
  • setApiUrl() guarda la dirección que se elige en la pantalla de login con el enlace "Dirección de la API". Así se puede cambiar sin tocar el código.

Catálogos fijos: salas, horarios, tipos de documento, tipos de butaca, marcas, tipos de producto y tipos de combo. Están escritos en el archivo porque la API no tiene endpoints para ellos.

Funciones de ayuda: nombreSala(id) y horaDeHorario(id) traducen ids a texto. Hacen falta porque FuncionDto solo devuelve ids: con ellas se muestra "Sala 1 · Tradicional · Sucursal 1" y "19:30".

3. api.js — el "cartero"

Es el archivo más importante para entender la comunicación con el backend. Toda llamada pasa por una sola función:

const peliculas = await api("/api/Pelicula", { query: { titulo: "avatar", pagina: 1 } });
await api("/api/compras", { method: "POST", body: { idFuncion: 5, idsButacas: [12, 13] } });

Lo que hace api(), en orden:

  1. Arma la URL. Une la dirección de la API con el endpoint y convierte query en parámetros (?titulo=avatar&pagina=1). Con URLSearchParams descarta los vacíos.
  2. Arma los encabezados.
    • Si hay body, agrega Content-Type: application/json y convierte el objeto con JSON.stringify.
    • Si hay token guardado, agrega Authorization: Bearer <token>. Así la API sabe quién es el usuario.
    • Si el body es un FormData (la subida de una portada), lo manda tal cual: el navegador arma el multipart/form-data.
  3. Hace el fetch. Si falla la conexión (la API está apagada o el certificado no está aceptado), lanza un error claro: "No se pudo conectar con la API…".
  4. Lee la respuesta. 204 significa que no hay contenido. Si no, intenta interpretarla como JSON; si no es JSON, la deja como texto.
  5. Si la respuesta es un error (!respuesta.ok):
    • Si es 401 y había sesión, el token venció: llama a alPerderSesion() y la app vuelve al login.
    • Lanza un ApiError con un mensaje legible y el código HTTP (err.status).

mensajeDeError() entiende los 3 formatos de error que devuelve la API:

La API devuelveEjemploQué toma
Texto planoBadRequest("La función ya empezó.")El texto
{ mensaje }Conflict(new { mensaje = "..." })mensaje
ProblemDetails (validación automática){ errors: { Email: ["..."] } }Une todos los mensajes

Si no reconoce el formato, usa un mensaje genérico según el código: 403 → "No tenés permisos", 404 → "No se encontró", etc.

Como el error lleva status, el resto del código puede reaccionar distinto según el caso:

catch (err) {
  if (err.status === 404) { /* "ningún cliente coincide" → aviso amarillo */ }
  else { /* error real → aviso rojo */ }
}

4. auth.js — sesión y roles

login(email, password): hace POST /api/Usuario/login, guarda el token recibido en localStorage y devuelve la sesión.

sesionActual() decodifica el token para saber quién está conectado:

  • Un JWT tiene 3 partes separadas por puntos: encabezado.contenido.firma. La del medio es JSON codificado en Base64.
  • decodificarToken() toma esa parte, la decodifica con atob y TextDecoder (para respetar acentos) y la convierte a objeto.
  • De ese objeto saca los claims que puso el backend en UsuarioService: id, correo y rol. Los nombres son largos porque son los ClaimTypes de .NET, por ejemplo http://schemas.microsoft.com/ws/2008/06/identity/claims/role.
  • Revisa exp (vencimiento). Si el token venció, lo borra y devuelve null.
  • Devuelve { idUsuario, email, rol, esAdmin, esInvitado }.
Para la defensa: el front lee el token pero no lo verifica, porque no tiene la clave secreta. Lo usa solo para mostrar u ocultar pantallas. La seguridad real está en la API: valida la firma en cada pedido y aplica [Authorize(Roles = "Admin")].

Modo invitado:

  • entrarComoInvitado() borra el token y guarda la marca cine_invitado = "1".
  • sesionActual() devuelve entonces un usuario con esInvitado: true.
  • No hay token, así que la API trata al invitado como anónimo. Solo puede usar los endpoints públicos ([AllowAnonymous]).

logout() borra el token y la marca de invitado.

abrirFormulario lo usan todas las altas y ediciones del panel de admin. Recibe un título, el HTML de los campos y una función onSubmit, y se encarga de:

  1. Validar los campos con las reglas de HTML (required, maxlength, type="email") mediante checkValidity().
  2. Deshabilitar el botón mientras se guarda, para evitar doble envío.
  3. Si onSubmit lanza un error (por ejemplo, el 409 "El DNI ya pertenece a otro cliente"), mostrarlo dentro del modal sin cerrarlo, para que el usuario corrija.
  4. Si sale bien, cerrar el modal.

6. cliente.js — la parte pública y de clientes

Datos compartidos

cargarPeliculasActivas() trae todas las películas activas y las guarda en un Map (id → película). Sirve para mostrar el título en la lista de funciones, porque la API solo devuelve idPelicula. Pide de a 100 en un while porque la API pagina.

Cartelera

  • initCartelera() llena los filtros de género y clasificación con /api/Catalogo/.... Usa Promise.all para hacer los dos pedidos al mismo tiempo.
  • cargarCartelera(pagina) llama a GET /api/Pelicula con filtros y paginación, y arma las tarjetas con template literals (texto entre comillas invertidas con ${...}).
  • A cada botón se le agrega un addEventListener("click", ...). El botón lleva el id en un atributo data-detalle="8", y el código lo lee con b.dataset.detalle.

Detalle de la película

abrirDetallePelicula(id) hace 3 pedidos en paralelo con Promise.all: la película, sus funciones y sus reseñas. Con eso arma:

  • El reproductor del tráiler (un iframe de youtube-nocookie.com) y el botón "Ver en YouTube".
  • La información, las próximas funciones (filtradas a las que todavía no empezaron) y las reseñas con el promedio de estrellas.
  • El formulario de reseña, según el perfil: cliente → formulario que envía POST /api/Resenia; invitado → botón "Iniciá sesión"; admin → nada, porque no tiene cliente asociado.

Funciones

buscarFunciones() elige el endpoint según los filtros: con fecha → /api/Funcion/fecha?fecha=...; con película → /api/Funcion/pelicula/{id}; sin filtros → /api/Funcion. Después filtra las que no empezaron y las ordena por fecha y hora. inicioFuncion(f) arma un Date uniendo la fecha y la hora de la función.

Butacas y compra

Es lo más elaborado; el paso a paso está en la sección 10.

  • mapaButacasHtml() dibuja la sala: ordena por número, arma filas de 10 con letras (A, B, C… con String.fromCharCode(65 + fila)) y le pone a cada butaca una clase CSS según su estado: occupied, premium o selected.
  • La selección se guarda en un Set (una colección sin repetidos). Al hacer clic se agrega o se quita, y la función redibujar() actualiza el mapa, la lista de elegidas y el total.
  • Las butacas preferenciales se detectan comparando precios: la API no informa el tipo de butaca, así que si cuesta más que la más barata, es preferencial.

Candy bar

cargarShop() lista los combos y los productos. Si el combo es más barato que la suma de sus productos, muestra el ahorro.

Comunicación con main.js sin importarlo

Cuando un invitado toca "Iniciá sesión para comprar", cliente.js dispara un evento propio:

window.dispatchEvent(new CustomEvent("cine:pedir-login"));

main.js lo escucha y vuelve al login. Así cliente.js no depende de main.js y se evita que dos archivos se importen entre sí.

7. admin.js — soporte y gestión

Carga perezosa: cada pestaña (Clientes, Películas, Funciones…) pide sus datos la primera vez que se abre, no al entrar. Lo controla el Set yaCargado junto con el evento shown.bs.tab de Bootstrap.

Todas las secciones siguen el mismo patrón:

cargarXxx()      → GET a la API → arma la tabla → conecta los botones de acción
formularioXxx()  → abrirFormulario → POST (nuevo) o PUT (edición) → recarga la tabla
eliminarXxx()    → confirm() → DELETE → recarga la tabla

enlazarAcciones() conecta todos los botones de una tabla de una vez. Cada botón tiene data-accion="editar" y data-id="5", y se llama a la función que corresponde.

Particularidades de cada pestaña:

  • Clientes (soporte): si la búsqueda devuelve 404, no lo muestra como error sino como aviso amarillo: "No se encontró ningún cliente que coincida…". "Ver reservas" abre un modal con la tabla de reservas del cliente.
  • Películas:
    • Los 8 catálogos se piden una sola vez (Promise.all) y quedan guardados.
    • Géneros, idiomas y actores son listas de casillas; fd.getAll("idsGeneros") devuelve todos los marcados.
    • La portada se sube después de guardar la película, porque hace falta su id. Se manda con un FormData a POST /api/Pelicula/{id}/portada.
    • Antes de subirla se valida tipo y tamaño, y se muestra una vista previa con URL.createObjectURL(archivo).
  • Butacas: la API crea de a una, así que para agregar N se hace un for con await. Van en orden para que la numeración sea correlativa. Si una falla, avisa cuántas se crearon.
  • Combos: al marcar productos o cambiar cantidades se recalcula en vivo la suma, porque la API no deja que el precio del combo la supere.
  • Administradores: formulario que llama a POST /api/Usuario/registro-admin y tabla con GET /api/Usuario/admins.

8. dashboard.js — estadísticas

  1. cargarDashboard() lee los filtros (desde, hasta, top) y hace los 3 pedidos en paralelo a /api/Dashboard/....
  2. dibujarKpis() calcula los indicadores de arriba sumando con reduce: entradas vendidas, recaudación, precio promedio (recaudación / entradas) y horario más elegido.
  3. grafico() es una función genérica que crea un gráfico de barras de Chart.js. Antes destruye el gráfico anterior con .destroy(), porque si no se superponen al filtrar. Configura los colores del sitio, el tooltip con varias líneas de detalle y si las barras van horizontales o verticales.
  4. Debajo de cada gráfico, tabla() arma una tabla con los mismos datos, para quien prefiera los números exactos.
  5. Los botones "Últimos 7 días" y "Últimos 30 días" calculan las fechas con restarDias() y recargan.

9. main.js — arranque y navegación

Al abrir la página:

const sesionGuardada = sesionActual();
if (sesionGuardada) mostrarApp(sesionGuardada);   // ya había iniciado sesión
else mostrarAcceso();                              // va al login
  • mostrarAcceso() muestra el login y llama a verificarApi(). Esa función hace un pedido de prueba a /api/Catalogo/generos para pintar el indicador verde API conectada o rojo Sin conexión.
  • Login: valida los campos, llama a login(), y si sale bien llama a mostrarApp(). Si la API responde 401, muestra "Correo o contraseña incorrectos".
  • Registro: comprueba que las dos contraseñas coincidan, llama a registrar() y vuelve a la pestaña de login con el correo ya escrito.
  • mostrarApp(sesion): muestra el correo y el rol arriba a la derecha; muestra Dashboard y Soporte solo si esAdmin; si es invitado, cambia el botón "Salir" por "Iniciar sesión"; carga las películas y la cartelera.
  • cambiarVista(nombre) es la navegación de la SPA: oculta todas las secciones y muestra la elegida. Si alguien no admin intenta abrir admin o dashboard, lo manda a la cartelera. Carga los datos de Funciones y Candy bar la primera vez que se abren.
  • Salir: logout() y después location.reload(), para empezar limpio.
  • Sesión vencida: con setAlPerderSesion se registra qué hacer si api.js recibe un 401: avisar y volver al login.

10. Ejemplo completo: un cliente compra 2 entradas

  1. Funciones → Buscar. buscarFunciones() llama a api("/api/Funcion"), filtra, ordena y dibuja la tabla.
  2. Clic en "Butacas". abrirButacas(funcion) abre el modal y dibujarSeleccion() pide GET /api/funciones/15/butacas. La API devuelve cada butaca con precio y disponible.
  3. Clic en las butacas 41 y 42. Se agregan al Set seleccion, y redibujar() las pinta en rojo y muestra el total, por ejemplo $13.000.
  4. "Comprar entradas". Pide confirmación con confirm() y después: 
    await api("/api/compras", { method: "POST", body: { idFuncion: 15, idsButacas: [101, 102] } });
    api.js agrega el token, así la API sabe qué cliente compra.
  5. En el backend: CompraController → CompraService (valida) → CompraRepository (factura, entradas y pago en una transacción).
  6. Respuesta 201 { nroFactura: 297, total: 13000 }. El front muestra el cartel verde "¡Compra realizada! Factura Nº 297" y vuelve a pedir las butacas: ahora la 41 y la 42 aparecen ocupadas.
  7. Si alguien las compró un segundo antes, la API responde 409. El catch muestra el aviso y, como err.status === 409, actualiza el mapa con el estado real.

11. Conceptos para nombrar en la defensa

  • Módulos ES (import / export) y separación de responsabilidades: cada archivo hace una sola cosa.
  • Asincronía: async / await y fetch; Promise.all para hacer pedidos en paralelo.
  • Manejo de errores con try / catch y una clase propia, ApiError, que lleva el código HTTP.
  • Autenticación con JWT: el token se guarda en localStorage, se manda en el encabezado Authorization y se decodifica para leer el rol.
  • Manipulación del DOM: template literals, innerHTML, classList, addEventListener y atributos data-* con dataset.
  • Seguridad en el front: escape de HTML con esc() contra XSS. Las validaciones del front son una comodidad; la seguridad real está en la API.
  • Estructuras de datos: Map para las películas por id y Set para las butacas elegidas y las pestañas ya cargadas.
  • Eventos propios (CustomEvent) para comunicar módulos sin acoplarlos.
  • Bootstrap desde JavaScript (Modal, Toast, Tab) y Chart.js para los gráficos.
